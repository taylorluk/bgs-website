## Why this isn't editorial pillars

The blog had **16 categories for 32 posts, 11 holding a single post**. The obvious fix
is to merge them into 4–5 broad pillars. SERP-overlap testing says that would be wrong.

| Topic A | Topic B | Shared top-10 URLs | Verdict |
|---|---|---|---|
| local SEO / Google Business Profile | getting more Google reviews | **0** | separate |
| marketing automation (beginner) | email automation sequences | **0** | separate |
| ecommerce CRO | landing page design | **0** | separate |
| landing page design | marketing funnel stages | **0** | separate |
| ecommerce CRO | marketing funnel stages | **0** | separate |

Every pair tested shares **zero** top-10 results. Google treats these as distinct topics,
so merging them into one pillar would target a search intent that doesn't exist.

Instead, each cluster is anchored on the **service page** — the commercial page that should
rank — with posts as spokes feeding it. That matches how an agency site actually earns money.

> **Caveat:** `WebSearch` queries a US index. These are UAE-intent keywords, so treat the
> overlap figures as directional. Re-run against a UAE-localised SERP source (DataForSEO
> with `location_code` for the UAE) before making expensive content bets.

## Internal link matrix

`cluster-plan.json` carries all **126** edges. The rules implemented in
`src/lib/related.js`:

| Link | Direction | Rule |
|---|---|---|
| Spoke → hub | post → service page | every post, mandatory |
| Hub → spoke | service page → post | every service page, mandatory |
| Spoke ↔ spoke | post → post | within cluster, rotated for even coverage |

Measured after implementation: **86% of related-post links now stay inside their cluster**
(was effectively 0% — category matching had to fall back to rotating the whole catalogue).
Minimum inbound internal links per post: **3**. No orphan posts.
